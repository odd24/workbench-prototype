# AI Agent 接入管理 UI 实施与维护方案

日期：2026-11-04。文档工作项：AG-106；功能实施范围：AG-107～111。本文定义待实施设计，不表示界面、管理 API、启动偏好或诊断功能已经存在。实际状态见 [AI_AGENT_PROGRESS.md](AI_AGENT_PROGRESS.md)。

本方案扩展 [AI_AGENT_PLAN.md](AI_AGENT_PLAN.md)，保留 AG-000～105 的已完成历史。当前可用接入步骤仍见 [AGENT_INTEGRATION.md](AGENT_INTEGRATION.md)，现有业务与安全边界见 [ARCHITECTURE.md](ARCHITECTURE.md)、[DATA_FORMAT.md](DATA_FORMAT.md) 和 [AGENTS.md](../AGENTS.md)。

## 1. 目标、决策与范围

### 1.1 产品目标

将接入管理放在工作台“设置 → AI Agent 接入”，让用户通过界面完成服务启用、客户端授权、Codex 配置引导和连接诊断。授权与当前数据空间、项目和知识库分类紧密相关，复用现有服务与页面比独立程序更便于操作和维护。

首期仍需用户在 PowerShell 执行一次界面生成的 MCP 登记命令。工作台不自动安装软件、不修改 Codex 配置、不启动聊天或模型 turn。

### 1.2 设计决策

| 编号 | 决策 |
| --- | --- |
| AG-DEC-006 | 在工作台设置内建设接入管理，复用当前单服务、Repository 与原生前端；不新增独立程序 |
| AG-DEC-007 | 首期提供授权管理、配置命令与分层诊断；自动修改 Codex 配置另行立项 |
| AG-DEC-008 | 本地管理 API 与 Agent 业务 API 分离；Agent 凭据不能调用管理 API 或给自身扩权 |
| AG-DEC-009 | 当前运行状态、下次启动偏好和连接证据分别表达；未初始化空间默认关闭 |
| AG-DEC-010 | 创建、轮换等多文件管理操作必须可查询、幂等和可恢复；不以单文件原子写宣称多文件事务安全 |

这些决策用于指导后续实施；新增公共契约或改变范围时先更新本方案和台账。

### 1.3 首期必须具备

- 查看当前工作空间、服务地址、启用状态与启动偏好。
- 无需重启整个工作台即可开启或关闭 Agent API，并可保存普通启动时的偏好。
- 创建、列出客户端，修改权限和范围，轮换凭据、撤销客户端。
- 为 Codex 或通用 MCP 客户端生成配置指引；提供正确转义的 PowerShell 命令。
- 分层检查环境、凭据配置、MCP 握手和实际请求证据，显示检查时间与修复建议。
- 处理刷新、失败、重复点击、请求超时、并发管理、服务重启和数据空间切换。
- 继续支持现有 CLI 授权方式与现有业务数据，无强制批量迁移。

### 1.4 不包含

- 自动修改 Codex 配置、自动安装 Codex/Python、启动模型或发送聊天消息。
- 网页聊天、网页独立入库确认、提案管理中心、扩展业务类型和远程接入。
- 托盘常驻、后台服务安装、多工作台统一管理或通用命令执行接口。
- 因配置检测而创建正式问题、知识文档或提案。

“整理并确认入库”仍遵守 [AGENT_USAGE.md](AGENT_USAGE.md)：完整预览后等待用户新消息确认当前版本，再提交。设置里的写入授权不代替该确认。

## 3. 页面与交互

### 3.1 入口与布局

设置页增加“AI Agent 接入”入口，进入独立管理视图，返回后保留原有设置页行为。内容复用已有设置卡片、按钮、表单、提示和确认对话框。

| 区域 | 展示 | 操作 |
| --- | --- | --- |
| 接入概况 | 当前空间、服务地址、运行状态、普通启动偏好、CLI 覆盖说明 | 开启/关闭、保存偏好、刷新 |
| 客户端授权 | 名称、ID、权限、项目/分类摘要、有效/已撤销 | 新建、编辑、轮换、撤销 |
| Codex 接入向导 | 环境检测、客户端、登记名称、命令、重启说明 | 检测、复制命令、重新生成 |
| 连接诊断 | 每项结果、证据来源、检查时间、下一步 | 检查、重试 |

名称与范围过长时允许换行或展开，不能只靠颜色表达状态。空库应有创建项目/分类的引导；尚无客户端、全部撤销、无可授权范围应有各自空状态。

### 3.2 首次使用

1. 打开页面只读查询；未建立身份时显示“尚未初始化”，不创建目录或令牌。
2. 用户开启接入；服务端确认 loopback、空间状态、配置目录及恢复状态。
3. 成功装配当前服务的 Agent 能力后显示“已开启”；保存启动偏好是可单独识别结果的操作。
4. 用户创建客户端，选择范围与权限；成功后进入接入向导。
5. 用户执行生成的命令，按指引重启 Codex 或开启新聊天。
6. 在 Codex 中只读查询 capabilities、项目和分类，确认实际工具可用。

### 3.3 客户端表单

| 字段 | 约束与默认值 |
| --- | --- |
| 名称 | 必填，去边缘空白，沿用不超过 100 字符限制；名称不是稳定 ID |
| 引导类型 | Codex 或通用 MCP，仅影响引导；不作为服务端身份或授权依据 |
| 权限 | 默认“只读查询”=read；“整理并确认入库”=read/propose/commit |
| 项目范围 | 默认不选；支持多选指定项目、明确选择全部（包括未来新增） |
| 分类范围 | 默认不选；支持多选指定分类、明确选择全部（包括未来新增） |

- 空项目范围不授权问题；空分类范围不授权知识文档。两者均空时 UI 阻止新建，服务端管理 API 同样校验。
- “全部”是独立选择，不以“勾选目前所有项目”暗示包含未来新增。
- “未分类”使用现有真实分类语义；项目显示名称并保留稳定 ID。
- 首期 UI 不提供三个底层 scope 任意拼接；现有 CLI/旧注册表兼容读取，不因打开页面就改写旧授权。旧组合无法直接映射时展示明细，用户明确选择新组合后才变更。
- 保存前展示扩大或缩小的范围。编辑带预期版本；冲突时保留输入并要求重新核对，不能静默覆盖。
- 刷新或离开未保存表单复用脏状态提示；提交失败保留选择，成功后重新读取磁盘事实。
- 创建结果只展示名称、ID、授权摘要和配置指引；不展示令牌或 token_hash。

### 3.4 轮换与撤销

轮换提示旧令牌即将失效；配置路径不变且桥接每次重读配置时通常无需重新登记。配置缺失、损坏或权限异常应引导修复，不能宣称成功。

撤销提示将失去访问权限，但不会自动移除 Codex 的 MCP 登记。保留撤销记录；已撤销客户端不能通过轮换或编辑恢复，需重新创建。关闭整体接入不会自动撤销授权。

## 4. 生命周期与启动偏好

### 4.1 配置规则

优先级：显式 CLI 参数 → 当前空间的本机偏好 → 默认关闭。保留 `--enable-agent`，拟增加互斥的 `--disable-agent`；二者仅覆盖本次启动，不隐式写偏好。

- 本机偏好放在操作系统用户配置目录，带 schema_version，不进入业务 ZIP、Git 或可移植数据。
- 按工作空间身份关联；身份未建立前一律默认关闭，不为读取偏好创建身份。
- 老安装、缺失配置默认关闭；损坏或未知版本拒绝自动启用，页面给出修复提示，保留原文件。
- 使用 `--agent-config-dir` 时沿用相同管理配置根目录，关闭状态也需记住该位置；不得在服务关闭后偷偷回退到另一凭据目录。
- 首次初始化、非 loopback、私人目录不可用或未决恢复异常时不得报告开启成功。
- 界面区分本次运行状态与下次普通启动偏好；CLI 覆盖时明确说明。

### 4.2 状态与并发

运行状态：未初始化、已关闭、开启中、已开启、关闭中、异常。启动偏好另有读取/保存结果，不与运行状态合并。

开启复用当前 Repository，不重新启动整个服务，不产生第二个业务仓储。保持既有 repository_switch_lock → repository.write_lock 的一致锁序；凭据管理锁的顺序在 AG-107 明确定义并测试，避免 CLI/UI 并发死锁。

关闭与提交按共享协调串行化：已进入受保护阶段的提交完成或进入既有恢复状态，之后新请求拒绝访问。关闭不取消回执，不删除提案，不跳过未决事务恢复；HTTP/stdio 断开也不能视为取消已接受提交。

运行切换与偏好保存分别返回结果。部分失败允许“当前已开启，但启动偏好保存失败”等状态，重试只补失败步骤。超时先查询状态，不反复切换；重启后按持久事实恢复。

## 6. 管理 API 草案

拟用 `/api/local/agent-management/`，独立于 `/api/agent/v1/`。以下是待实施契约，精确 JSON Schema 在 AG-107/108 编写测试前固定。

| 方法与相对路径 | 功能 | 写入约束 |
| --- | --- | --- |
| GET `status` | 初始化/运行/偏好/空间及环境摘要 | 不初始化、不生成凭据 |
| PATCH `runtime` | 开关及可选启动偏好 | 当前空间、expected_version、稳定 request_id |
| GET `clients` | 脱敏列表，含配置版本和失效范围 | 不返回凭据/摘要/任意文件内容 |
| POST `clients` | 创建授权 | 当前空间、request_id、名称、权限与范围 |
| PATCH `clients/<id>` | 修改名称与授权 | expected_version，禁止修改客户端 ID/空间身份 |
| POST `clients/<id>/rotate` | 轮换 | expected_version、request_id |
| POST `clients/<id>/revoke` | 撤销 | expected_version、request_id；重复请求返回原结果 |
| GET `clients/<id>/setup` | 当前平台接入说明/命令 | 仅服务端派生配置路径，不接受任意文件路径 |
| POST `clients/<id>/setup` | 按用户登记名称生成命令 | workspace_id、name；名称仅字母开头的字母/数字/下划线/连字符，最多 64 字符；不执行命令 |
| POST `clients/<id>/repair` | 将配置 origin 修复为当前服务 | expected_version、workspace_id、request_id；不接受任意地址 |
| POST `diagnostics` | 发起当前有效客户端诊断 | 有限时、有限输出，不接受 shell/任意 args |
| GET `operations/<id>` | 查询管理操作/诊断结果 | 当前管理会话和空间，脱敏输出 |

状态响应至少区分 workspace_id（未初始化可空）、runtime_state、startup_preference、effective_source、配置版本与错误提示。普通 Agent capabilities 不返回管理会话或本机配置。

错误统一包含 code/message/retryable/details/request_id；适用时区分 400 参数无效、403 管理拒绝、404 客户端/操作不存在、409 空间/配置版本冲突、503 环境不可用、500 未处理失败。日志与 details 不含令牌、配置正文或原始敏感异常。

## 7. 管理访问边界

- 服务绑定和请求来源均限本机 loopback；非 loopback 模式下管理 API 禁用，不因 Host 字符串看似本机而放行。
- 复用 Host/Origin/跨站校验；写入要求受信任同源 JSON 请求及服务端签发的管理会话校验值，不开放 CORS。
- 管理会话仅向工作台同源页面提供，含服务生命周期约束；过期、重启及空间切换后拒绝旧写入。校验值不进 URL、日志、localStorage 或 Agent 工具返回。
- Agent Authorization 不得用于获取管理会话、配置路径、诊断或扩大权限；管理路由不加入 MCP 工具清单。
- 缺少 Origin/Fetch 元数据的管理请求采用明确的拒绝/专用会话校验策略，不能仅以“浏览器通常会发送”作为安全依据；AG-107 固定测试。
- 凭据继续由后端私人目录持有；页面和通用 Agent 返回都不含明文 token、token_hash、完整注册表。
- 仅本地管理视图可接收生成指引所必需的本机路径；这些路径不进入业务内容、业务导出或远程可见响应。

管理会话用于防跨站误用，不是同用户恶意进程的隔离边界；不将本机无认证 UI 或文件权限宣传为操作系统沙箱。

## 8. 凭据、授权与多文件一致性

### 8.1 兼容与锁

沿用 clients.json、每客户端配置文件与现有认证。新元数据必须有缺省值和旧格式读取；打开页面不批量重写注册表。引导类型等 UI 元数据可选，不能改变业务鉴权身份。

所有 CLI/UI 创建、修改、轮换、撤销共用配置目录跨进程锁。鉴权及正式提交在共享协调内重查最新授权，避免在锁外读旧权限后继续提交。配置编辑使用明确版本，冲突不静默覆盖。

### 8.2 管理操作可靠性

管理操作日志放在私人配置目录，与业务提案操作日志分开；不借用业务 request_id，不创建业务条目。记录操作 ID、幂等映射、阶段和恢复所需的受保护快照，敏感材料遵循私人目录权限。

- 同一 request_id 相同输入查询/返回原结果，不同输入返回 409。
- 创建和轮换先登记可恢复操作，再修改涉及文件，最后持久完成结果。
- 任何时刻不能同时接受轮换前后两个令牌；切换点及恢复规则在 AG-108 形成明确状态表和故障测试。
- 配置文件已更新但注册表未更新等阶段失败，不报告成功；重启或查询根据可证明的阶段补齐原操作，不能重新生成第三个令牌掩盖失败。
- 出现第三方修改、损坏或无法证明的状态时停止该客户端管理变更，返回需修复；不得覆盖未识别的新配置。
- 失败影响限于相关客户端/管理操作，不擅自把无关业务读写锁死；业务未决提交仍沿用原阻写规则。
- 完成后重读校验；日志清理须保留必要的幂等回执，敏感快照有明确清理策略，不能永久无界增长。

精确日志格式、保留时间、修复命令与降级条件是 AG-108 开工设计门槛，必须先补入本节再编码，不沿用业务提案的 7/30 天规则当成已确定事实。

AG-108 开工契约（2026-11-04）：私人目录 management-operations/<operation_id>.json 使用 schema_version=1、workspace_id、request_id、input_digest、client_id、state（prepared/completed/recovery_required）、before_client/after_client、before_config/after_config 与 result。路径仅由服务生成的 UUID 派生；request_id 的查找通过摘要文件名，不接受任意路径。配置先写，注册表后写，注册表单次原子替换是新凭据生效点；完成后同一次日志替换清除所有凭据快照，仅保留脱敏回执/摘要，精简回执长期保留以保证幂等，未决快照不自动清理。

分类授权迁移在原业务变更前收窄旧名称访问，业务成功后授予新名称；中途失败保持收窄，提示重新核对授权，不自动扩大到“未分类”。旧名称复用不能恢复原访问；范围编辑的配置版本必须变化。具体故障证据与剩余的跨文件边界写入完成记录。

### 8.3 范围的生命周期

全部范围的既有语义保留。任何额外访问均需明确授予；预览过的提案也必须在正式提交时检查最新权限、范围与目标版本。

## 11. 空间、迁移、备份与修复

| 场景 | 预期处理 |

### 12.1 AG-107 开工契约

- 锁序固定为 repository_switch_lock → 当前 repository.write_lock → 私人配置目录的跨进程锁；CLI 仅持最后一层，不反向获取服务锁。诊断子进程不得在持业务锁时等待 HTTP。
- 管理 GET 需 X-Workbench-Management: 1，且拒绝跨源/跨站/Agent Authorization；status 返回本次服务/空间的短期 management_token（1 小时），仅保留内存。所有管理写入另需同源 Origin 与 X-Workbench-Management-Token；过期或空间切换后重新获取 status，不自动重放写入。
- PATCH runtime 必填 workspace_id（未初始化时 null）、expected_version、request_id，可选 enabled/startup_preference（至少一个布尔值）。未知字段/错误类型返回 400；空间或版本不一致返回 409；失效会话/非同源返回 403。
- 本机偏好为私人工作空间目录 runtime.json：schema_version=1、workspace_id、startup_enabled 布尔值。缺失为 false；损坏/未知版本保留原文并阻止自动启用，status 提示错误。配置损坏须停服备份后核对修复，不自动覆写。
- 运行切换先完成，再尝试独立偏好保存；响应含状态及 preference_error。运行状态和结果由查询确认。runtime request_id 在服务生命周期内用于去重；重启后查询最新状态再按新版本设置目标状态，不把内存去重用于凭据或正式提交。
- GET operations/<request_id> 查询本服务已接受的运行设置结果；不返回任何秘密。AG-108 将扩展持久的凭据管理操作。
