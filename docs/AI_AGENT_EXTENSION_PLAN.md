## 1. 目标、范围和交付边界

把原方案列出的五类后续能力拆成可独立验收、可独立回退的工作项：

1. 待办（todo）与结构化信息（info）的查询、新建、追加和更新。
2. 本机网页独立批准，使指定提案不能通过 Agent 自报确认直接提交。
3. 提案管理页，支持查阅、筛选、完整预览、批准、取消和结果查询。
4. 其他 Agent/MCP 客户端的真实兼容验证与接入文档。
5. 独立的远程 MCP 传输与授权边界，保留本机服务默认仅监听 loopback。

继续保持单用户、Markdown 事实源、Python 标准库后端、原生前端、无应用运行时第三方库和无构建步骤。远程网关、TLS 终结及身份服务属于可选部署设施，需要在远程设计门槛确认，不默认安装或作为本地使用前提。

本轮不包含聊天/模型调用、模型 API Key 管理、自动抓取聊天、自动执行命令、附件写入、删除/历史恢复工具、批量跨提案事务、概念图生成或多用户协作。网页批准只表示持有本机管理会话的操作者批准，不能声称已认证某个现实人的身份。

## 3. 公共契约与升级策略（AG-116）

### 3.1 类型和授权

- 拟在私人客户端配置及服务端授权记录增加 `kinds`，只接受 issue/document/todo/info 中的显式集合。缺失字段按旧集合 issue/document 解释，不能解释为全部。
- 有效权限 = scopes ∩ kinds ∩ 项目/分类范围；新增类型需要操作者在管理 UI/CLI 明确授权，复用 CredentialManager 的日志、锁、预期版本与恢复。轮换令牌不能附带扩权。
- read/propose/commit 仍分别校验；网页执行不能突破原客户端的范围。撤销、权限收窄、项目删除及分类迁移必须即时影响已有提案。
- 引用校验同样检查类型权限，不得通过正文引用、search、catalog、current_item、错误信息或摘要泄露不可见类型。
- `catalog` 拟增加可选 kind；省略保持现有 issue 工作流语义，todo 返回所属项目适用工作流，info 不返回状态。

### 3.2 能力与协议兼容

- 保留 `/api/agent/v1` 和现有 12 个 MCP 工具名；增加类型枚举和按类型字段校验。capabilities 拟增加 `kind_operations`、`kind_fields`、`confirmation_modes`、`default_confirmation_mode`、类型权限及各类限额。保留旧 confirmation_mode，仍表达旧客户端默认行为。
- 现有请求不携带新字段继续运行；未知字段仍报 400。支持 create/append/update 的具体组合以 capabilities 为准，不能由客户端猜测。
- 新客户端必须先查能力；旧客户端依旧只调用已认识的类型，不依赖旧客户端理解新枚举。必要时先在兼容测试中验证工具目录刷新行为。
- 字段缺省表示保留旧值（更新）或使用预览中可见的服务端默认值（新建）；显式清空必须与缺省区分。completed、ID、时间和历史由服务端生成。

### 3.3 流程数据兼容

- 不修改业务 Markdown 格式，不批量迁移旧文件。新客户端授权和新提案流程字段采用显式 schema 版本；旧 schema=1 按旧类型、agent_attested 和旧摘要算法读取。
- 新 schema=2 拟记录有效类型、确认策略、批准记录及摘要算法版本。版本是持久格式版本，不等同 HTTP 或 MCP 协议版本。
- 新预览摘要覆盖类型字段、完整归一化内容、警告和确认策略；绝不能因升级静默重算旧已预览摘要。旧提案继续旧流程；要改成网页批准需生成新版本、重新预览确认。
- 所有读取/清理/report/abandon/恢复/精简回执路径先识别 schema；未知版本保留证据并拒绝不安全写入。新旧日志混合恢复、停服文件备份和降级前处理在途日志必须有测试。
- 降级后不能处理新日志时应拒绝写入并提示使用匹配版本；不以删除 .agent 实现回退。

## 4. 待办和结构化信息（AG-117、AG-118）

### 4.1 拟定字段矩阵

| 类型 | create | update | append |
| --- | --- | --- | --- |
| todo | title/project_id/body/tags/status/priority/due | title/body/tags/status/priority/due；不迁移项目 | 只接受非空 body，合成全文；其他字段修改用 update |
| info | title/project_id/body/tags/info_fields | title/body/tags/info_fields；不迁移项目 | 只追加正文，不隐式合并 info_fields |

- todo 的 status 来自现有项目工作流，completed 根据所选状态推导；拒绝用户直接传 completed。due 拟接受有效的 `YYYY-MM-DD` 或 null，禁止自动时区换算，开工需核对现有网页与旧文件习惯；若不一致先登记再调整契约，不迁移旧值。
- info 无 status/priority/due/completed；不增加 command 子类型，也不提供执行按钮。info_color 第一阶段不开放给 Agent，更新时保留原值，新建使用已有默认值。
- info_fields 是有序数组，每项只接受 name/value/可选 note；按现有归一化器读取旧格式。提交前对类型、空字符和未知键严格检查，防止宽容旧格式读取掩盖新请求错误。
- 字段顺序、value/note 中的换行、引号、首尾空格必须经过提案→预览→Markdown→重载往返验证。多行值用已有序列化格式，禁止另存一份 JSON 作为业务事实源。
- 拟定上限：200 项字段；name 200 字符；单项 value/note 各最多 64 KiB UTF-8；body + 全部结构化字段合计最多 256 KiB UTF-8；沿用 1 MiB 请求上限。capabilities 明示，服务端执行；实施前通过现有大数据样本校准并记录最终值。

### 4.2 完整预览与保存

todo 预览展示项目、标题、正文、标签、状态、优先级、截止日期和推导出的完成标记。info 展示完整有序字段及正文，不能把多行字段折叠成不可检查的摘要；差异展示新增、删除、重排和具体值变化，不引入持久字段 ID。

更新必须完整读取现值及 revision，保留未开放的附件、links、颜色和旧元数据。归一化、历史、原子写、缓存失效、持久幂等回执与现有问题/文档相同。扩大恢复目标白名单时只接受对应项目下 todos/infos 的合法稳定 ID 路径，不放开任意相对路径。

两个工作项均须覆盖搜索、引用、分段读取、重复提交、项目消失、工作流改名、外部修改和恢复；新链接 `/?item=todo|info&itemId=...` 必须验证类型与 TODO-/INFO- 前缀相符，不能借链接打开不匹配记录。

## 5. 提案管理页（AG-119）

### 5.1 页面和权限

在现有 AI Agent 设置下增加“提案管理”入口，通过独立 feature 装配，复用统一 API、对话框和只读 Markdown 渲染。默认列出当前空间提案，可按客户端、类型、状态和操作筛选，默认每页 20、最大 100；详情按需加载，避免一次读入全部正文。

页面展示客户端名称/ID、提案 ID/版本、创建/过期时间、归属、状态和结果。详情必须有完整正文、结构字段、差异、警告和来源说明。清理后只剩回执时明确显示“正文已按保留规则清理”，不能用残缺预览批准。

本机操作者可管理当前空间各客户端提案；普通 MCP 仍只能读自己的提案。读取详情必须经过管理会话，不能借只读状态接口、业务搜索或直接静态文件访问获取提案。

### 5.2 拟定本机路由

统一前缀 `/api/local/agent-management/`，下表为待实现契约，不增加 MCP 管理工具。

| 方法/路径 | 行为 |
| --- | --- |
| GET proposals | 分页/过滤列表，只返回脱敏摘要 |
| GET proposals/{id} | 当前状态、版本、归属、当前授权是否可用、回执；不自动重放提交 |
| GET proposals/{id}/preview | 完整预览；AG-120 扩展管理会话绑定的预览凭据 |
| POST proposals/{id}/cancel | expected_version + request_id；取消未开始提交的当前版本 |
| POST proposals/{id}/approve | AG-120 提供，接受版本、摘要、预览凭据和 request_id，不接受正文 |
| GET proposal-actions/{request_id} | AG-120 提供，查询本机批准/取消请求结果及恢复状态 |

路由复用 loopback、Host/Origin/跨站限制、独立短期管理会话和空间绑定；拒绝 Agent Authorization，不返回凭据、机器路径或子进程输出。不能复用通用 operations 查询掩盖不同日志职责。

### 5.3 第一阶段能力和交互

AG-119 先交付查阅、完整预览、取消及结果打开；批准按钮在 AG-120 验收前不可用。第一阶段不在页面编辑提案，提示回原客户端修改后重新预览；以后增加编辑器须独立登记，不复制现有编辑器。

状态文案复用 draft/previewed/committing/committed/conflicted/cancelled/expired/recovery_required。双击防重、慢请求、会话失效、切换空间、原提案变更、缺失正文及恢复中分别给出可操作提示。进入详情或分页不能静默保存/取消已有记录编辑器草稿。

## 6. 网页独立批准（AG-120）

### 6.1 确认策略

- 拟支持 `agent_attested` 和 `local_web`。既有客户端、提案和操作默认保持 agent_attested；本机设置可将客户端的最低确认要求收紧为 local_web，Agent 只能请求同等或更严格模式，不能降低策略。
- 提案保存有效 confirmation_mode；create/revise/preview/get 均返回。local_web 时 MCP commit 必须报 confirmation_required 并返回无秘密的本机管理入口，不能仅附加 user_confirmed=true 就通过。
- 管理侧收紧策略后，旧自报确认提案不可继续提交；升级提案版本/摘要并重新预览。降低客户端最低要求也不自动降低已有 local_web 提案。
- 网页批准要求原客户端仍有效且具备 read/propose/commit、对应类型和归属权限；页面不替客户端补权限。只读/已撤销客户端的提案可查看/取消，但不能批准写入。
- local_web 不向 MCP 返回可兑换的批准令牌；远程工具同样不能调用本机批准路由。独立通道减少对 Agent 自报的信任，仍不能防御已控制本机用户环境的程序。

### 6.2 批准流程

1. 管理页请求完整预览，服务生成仅供当前管理会话的短期预览凭据，拟有效 10 分钟，绑定 workspace/proposal/version/digest/确认策略及客户端授权版本。凭据只在内存和页面内存，不写 URL、日志或 localStorage；重启/会话失效需重新预览。
2. 页面完整呈现内容和差异后才启用“批准并入库”。超大内容、缺失字段、摘要或权限变化必须阻止批准，不能靠滚动到底证明用户阅读。
3. 用户点击并确认后提交版本、摘要、凭据和稳定 request_id。服务在协调锁内重查会话、权限、目标 revision、过期时间、工作流/分类和归一化结果；任一变化返回冲突，保留候选内容，不自动重试。
4. 持久记录批准来源为 local_web、所批准版本/摘要、时间、操作 ID 和请求摘要；不持久保存会话秘密。随后调用同一领域准备写入及 ProposalStore 提交，不建立网页专用 CRUD。
5. 请求成功返回原提交回执；响应丢失先查询 proposal-actions 和原提案。原请求重复返回同一结果，同 request_id 不同输入报 409；多个标签页/客户端同时批准只写一次。

### 6.3 批准持久化和恢复

拟在 .agent 下增加本机提案操作日志，与业务提交日志关联 operation_id。批准记录先于目标写入持久化，最终回执关联相同版本/摘要；写后崩溃沿用现有 before/after/第三方内容判定，不重建已删除内容。

批准、最终校验与提交准备在同一协调区间完成，不设计可长期转交给 Agent 的“已批准待提交”状态。崩溃后只有持久日志证明批准及写入准备完整时才允许恢复原事务；只有预览凭据或未完成批准日志不能推断用户批准。恢复前重新检查撤销/收窄：尚未尝试写入时停止；已进入应用阶段时依据磁盘事实核查并完成必要回执，禁止把已应用操作重放为新操作。此边界必须通过各阶段中断证明。

详情读取本身不触发未经批准的新提交；既有 committing 事务的恢复应明确标注。批准凭据不能替代磁盘持久记录。批准后修改提案一律新版本重新批准，网页与 MCP 并发修改旧凭据立即失效。

## 7. 其他 Agent 兼容验证（AG-121）

不预先宣称兼容任意客户端。实施时选择至少一个非 Codex、可实际安装并隔离配置的本地 MCP 客户端；选择与版本在开工台账记录。客户端不可获得时，该项受阻，不能用自制 MCP 测试程序代替真实客户端。

| 验证层 | 必须记录的证据 |
| --- | --- |
| 协议 | 客户端/OS/协议版本、initialize、tools/list、Schema 接受、UTF-8、通知/错误/取消/断线 |
| 查询 | 四类型作用域过滤、分段读取、分页、引用权限、未知字段错误 |
| 写入 | 四类型 create/append/update、完整预览、修改后旧确认失效、取消/超时查询/重复提交 |
| 确认 | agent_attested 按规则展示后等待新用户确认；local_web 不能自报绕过，完成网页批准往返 |
| 故障 | 撤销/轮换、服务重启、空间错误、业务错误 isError、stdout 无额外输出 |

先使用真实客户端的工具调用设施，在不启动模型 turn 的方式下验证协议。若需模型行为验收，单列用户可手工执行的步骤与所需环境，未经授权不启动付费调用，不把工具调用测试描述成模型遵守确认规则的证明。

通用接入文档提供 command/args 数组、配置位置的客户端版本说明和脱敏错误示例，不读取/覆盖真实用户配置。维护兼容矩阵：已实测、未验证、不支持及具体原因；升级客户端必须重新跑对应契约。协议版本扩展先核对官方规范并登记，不借兼容工作引入运行时 SDK。

## 8. 远程 MCP（AG-122～125）

### 8.1 架构与不可越过的边界

拟采用独立远程 MCP 适配进程，通过受限本机连接调用同一 AgentService；不另建 Repository、不直接读写业务文件、不把现有 4173 端口整体暴露。工作台网页、静态资源、本机管理、凭据管理和 Codex 登记始终只在本机可用。原 stdio 接入保持独立可用，远程默认关闭。

拟采用固定版本的 MCP Streamable HTTP；确切协议版本、HTTP 会话/流/取消/恢复语义、认证元数据及客户端支持须在 AG-122 重新核对官方规范并锁定，不能将当前 stdio 的 2025-11-25 验收外推为已支持远程。

可选部署设施限定为已有的 TLS 反向代理和标准身份服务。网关负责 TLS/网络入口，应用负责工具授权、工作空间和确认；不把“网关已登录”当作业务授权。此部署方式不改变本地零运行时依赖，但新增外部服务、运维成本和秘密保管；AG-122 必须列明目标环境及批准的依赖，未确定不得启动远程实现。

### 8.2 AG-122 必须形成的设计决策

1. 确定仅私有网络还是公网可达、固定外部 origin、证书来源/续期、反向代理可信边界、身份提供方和撤销能力；给出脱敏部署配置及威胁模型。
2. 首选由现有身份服务发 OAuth 访问令牌，工作台充当受保护资源；明确 issuer/audience/resource、scope、有效期、客户端授权流程及用户主体映射。不自制密码登录或把本地长效令牌发给远程客户端。
3. 在无第三方运行时库约束下，优先评估固定 HTTPS introspection 端点进行令牌验证；必须确认身份服务支持所需的令牌 audience、撤销、元数据及所选客户端授权流程。不能用未验证 JWT 载荷或自写不完整签名算法替代验证。
4. 验证超时/缓存窗口/撤销时效/身份服务离线行为，默认鉴权失败关闭；如需新库、托管服务或不同部署架构，先记录替代方案与取舍，再取得新的实施授权。
5. 明确远程主体→本机专用客户端的服务端映射：每主体单独授权 kinds/scopes/项目/分类，禁止请求自报 client_id 或换库；映射和秘密只在私人目录，本机 UI/CLI 管理并有持久回执。
6. 远程新提案强制 local_web；不允许 Agent 自报批准，批准只在本机。用户需要异地批准时属新范围，不能把管理页顺带公网化。
7. 给出攻击面、回退/停用和验收环境清单；没有目标身份服务和至少一个支持所选传输/授权的真实客户端，不得标记设计完成。

这些是后续设计门槛而非本次要求用户立即提供的信息。AG-122 前本机功能可独立推进。

### 8.3 AG-123：授权与网络入口

- 远程专用启用开关、绑定地址和受信 origin 采用私人配置，不复用本机 startup_enabled。默认关闭；缺失/损坏配置禁止远程启动。
- TLS 入口只转发固定 MCP/必要标准元数据路由，不代理 `/api/*`、静态站点或管理接口；后端端口限制 loopback 或受保护的专用连接。可信代理列表明确，客户端不能伪造转发头改变 origin/身份。
- 固定 issuer/introspection/元数据地址由管理配置决定，不接受请求内任意 URL；禁止跨主机重定向、私网探测及任意代理，验证 TLS 与请求时限，避免 SSRF。
- 限制并发、请求大小、每主体速率、连接数和会话期限；拟初值每主体 120 次/分钟、最多 4 个并发请求、请求 1 MiB，流连接有独立数量/空闲超时。AG-122 结合协议长流语义校准，不能用固定短超时破坏正常传输。
- Bearer、会话 ID、原始正文和 introspection 响应不写访问日志。使用不可猜测请求 ID 关联脱敏审计；时间、主体内部 ID、工具、结果码足够定位，保留期限与最大容量明确可配置。
- 身份令牌不能直接用作现有本地 Agent Bearer；内部映射凭据不返回远程，撤销与权限收窄沿用现有共享协调和凭据管理。

### 8.4 AG-124：远程协议适配

共享工具声明和业务服务，仅增加协议/传输适配与远程主体鉴权。会话绑定主体、客户端与空间；逐请求重查权限，初始化成功不能永久授权。断流/取消不得误报回滚已提交事务，提交超时返回同提案查询指引。

仅发布当前经过实测的 tools 能力；不增加 prompts/resources/通用 HTTP/本机管理能力。严格遵守选定协议版本的内容类型、Accept、版本协商、HTTP 状态码、会话隔离和流关闭语义。不根据猜测拼出一套近似远程 MCP；AG-122 的规范矩阵是测试依据。

MCP 会话不决定幂等性，仍以持久 request_id/proposal/version/digest 为准；重连、反向代理重试和服务重启不能重复创建。远程停用立即拒绝新调用；已开始的持久事务按现有日志核查，不能直接杀进程并丢弃回执。

### 8.5 AG-125：部署、验收和停用

仅用一次性数据、测试身份、临时凭据及独立测试配置，在真实 TLS/代理/身份服务/客户端拓扑验收。必须包含四类型完整往返、网页批准、过期/撤销/轮换、跨主体/空间拒绝、断流/超时/重试、磁盘故障/重启恢复、代理头伪造、请求超限、身份服务不可用及证书错误。

演练一键关闭远程入口且本机网页/stdio 接入仍可用；撤销测试主体并移除测试网关登记，保留必要恢复证据。交付部署手册、最小路由代理示例、秘密备份/轮换说明、监控及异常响应，不替用户部署真实公网服务。缺少真实拓扑或授权时记录受阻条件，不能以本地模拟通过宣称远程可用。
