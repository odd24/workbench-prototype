# 通用 AI Agent 接入实施方案

日期：2026-11-03；实施验收：2026-11-04。状态：AG-000～105 已完成；实际验证与剩余边界见 [AI_AGENT_ACCEPTANCE.md](AI_AGENT_ACCEPTANCE.md)。

本方案定义新增功能，不改变已完成 RF-000～RF-505 的历史状态。实施状态见 [AI_AGENT_PROGRESS.md](AI_AGENT_PROGRESS.md)，执行约束见 [AGENTS.md](../AGENTS.md)。下文保留设计时的范围与契约，当前运行和授权命令以 [接入说明](AGENT_INTEGRATION.md) 为准；后续边界不属于已实现范围。

## 1. 已确认需求与范围

- 优先在 Codex 对话中使用；工作台继续承担正式数据存储、浏览、编辑和管理。
- 用户主动要求整理当前问题或知识总结时触发，不自动扫描、同步或监听所有聊天。
- 每次先展示完整预览，用户在 Codex 明确确认当前版本后才正式入库；修改预览必须重新确认。
- 业务接口面向通用 Agent；Codex 是第一个适配和验收客户端，不能把 Codex 聊天 ID、模型名、登录方式写成业务前置条件。
- 第一版支持问题和知识文档的新建、追加和修改。预留待办与结构化信息，但不提前宣称支持。
- 使用已有项目、标签、工作流和文档分类；不自动创建项目、分类、标签或状态。
- 不包含网页聊天、模型调用、API Key 管理、自动执行命令、附件上传、概念图生成、删除工具、自动总结任务、跨聊天抓取及向量数据库。
- 不修改用户 Codex 配置、不连接真实数据进行写入验收；接入测试用独立配置和一次性目录。

### 1.1 用户流程

1. 用户说“将这次排查整理到 A 项目”或“整理成知识文档”。
2. Agent 查询允许访问的项目/分类，搜索相似条目，再按需读取正文。
3. 归属不明确时询问；相似条目只提示候选，不自动认定重复或合并。
4. Agent 提交结构化候选内容，服务端校验并生成独立提案。
5. Agent 展示服务端返回的预览：提案 ID/版本、操作、归属、标题、全部正文、字段变更、关联及警告。更新同时展示差异。
6. 用户修改要求产生新版本，旧预览凭据失效；用户取消则取消提案。
7. 用户明确确认后，Agent 提交该提案版本和预览摘要；提交请求不得携带新正文。
8. 服务端重新校验权限、版本和配置，保存后重新读取，返回正式 ID、位置和网页链接。
9. 超时先查询提案状态；已提交返回原回执，不能重新创建一份内容。

### 1.2 内容规范

问题建议段落：现象、环境与适用版本、复现条件、排查过程、证据、已验证结论、推测/待验证项、后续事项。知识建议段落：适用范围、前提、步骤、验证方法、常见问题、来源关联。无材料的段落可省略，不能补造版本、日志、结论或日期。

这些是正文整理模板，不新增 document_type 或 issue 子类型。命令与日志保持换行、引号和空格，不执行。只提交必要的总结及关键证据，不默认归档完整聊天；来源只保存用户允许的简短说明和可选外部引用，不要求可访问的聊天链接。

## 2. 代码核查与前置差距

| 当前事实 | 影响及处理 |
| --- | --- |
| `workbench/records.py` 更新记录前保存历史 | 复用现有历史语义；补齐并发下唯一版本名和失败测试 |
| `workbench/documents.py` 更新文档没有保存历史 | 增加文档历史读取/恢复和网页入口，之后才开放 Agent 文档更新 |
| 记录创建使用 `_record_id_lock`，文档创建缺少同等 ID 锁 | 两类创建都进入统一写入协调，防止重复 ID |
| 更新方法没有 expected revision 校验 | 新增内容版本前置条件，网页与 Agent 都使用，不能只保护 Agent |
| 前端已有签名轮询与冲突会话 | 复用冲突 UI；后端 409 必须保留草稿并进入冲突流程 |
| 导航模块保存页面状态并清理 hash | 正式条目深链接需要实现，不能先返回不存在的锚点 |
| HTTP 使用 `SimpleHTTPRequestHandler` 从仓库根提供静态资源 | 启用接入前收紧静态资源白名单，防止数据目录、凭据和源码被静态路由读出 |
| 当前完整导出遍历业务目录并排除部分机器文件 | 显式决定新增提案、凭据、操作日志的导出/迁移策略，不能依赖名称猜测 |

现有文档中“冲突处理”描述的是交互能力，不等于服务端原子比较写入；记录历史也不能推断为文档已有历史。本方案记录这些差距，当前架构/数据文档只在实现后更新事实。

## 3. 架构与模块边界

```text
Codex / 其他本地 MCP 客户端
  → Python stdio MCP 适配器（不直接访问业务文件）
  → 127.0.0.1 上的 /api/agent/v1/*（独立凭据）
  → Agent 服务：授权、提案、预览、提交、回执
  → 共享写入协调 + 现有领域仓储
  → Markdown / JSON / 历史

工作台网页 → 现有 /api/* → 同一共享写入协调和领域仓储
```

第一版采用本地 stdio MCP，不实现远程 MCP HTTP 服务。桥接器只调用工作台 Agent HTTP API，不另起 Repository 写同一目录，不在工作台关闭时偷偷启动另一个写入进程。服务未启动时返回明确提示，用户正常启动后可重试。桥接器不调用模型、不读取 Codex 内部聊天数据库。

保留 Python 标准库、无第三方运行时依赖的基线。MCP 仅实现已声明且经真实客户端验证的版本与工具子集，不自制另一种“类似 MCP”协议。拟以 `2025-11-25` 握手协议作为首个互操作候选，AG-104 实施前验证目标 Codex 实际支持情况；不声称这是最新版本。若目标客户端不支持，先登记协议调整和兼容测试，不静默引入 SDK 依赖。

拟定文件职责：

| 文件 | 职责 |
| --- | --- |
| `workbench/write_coordinator.py` | 单服务共享写锁、版本检查、提交恢复协调 |
| `workbench/agent_service.py` | 面向所有 Agent 的业务操作，调用领域仓储 |
| `workbench/agent_proposals.py` | 提案版本、摘要、状态与原子持久化 |
| `workbench/agent_security.py` | 客户端凭据、作用域、工作空间绑定与输出脱敏 |
| `workbench/agent_http.py` | Agent 路由解析和错误映射；由现有 Handler 分派 |
| `workbench/mcp_stdio.py` | JSON-RPC/MCP 生命周期、工具目录及 HTTP 适配 |
| `agent_bridge.py` | 独立 stdio 启动入口，无领域规则 |
| `workbench/records.py`、`documents.py` | 共享校验、可重放写入准备、历史与正式持久化 |
| `js/core/navigation.js`、编辑会话/冲突模块、`app.js` | 深链接、版本条件、历史入口及现有 UI 装配 |
| `docs/AGENT_INTEGRATION.md` | 实现后提供通用客户端接入、Codex 配置及故障排查 |

不得在桥接器复制 ID 分配、Markdown 序列化或 CRUD；预览与提交复用同一归一化函数。`server.py` 只增加必要的 CLI/装配入口。新模块边界按台账登记后逐项实施。

## 4. 通用接口契约（v1）

HTTP 业务版本与 MCP 协议版本独立。所有资源通过 ID 引用；客户端不得传业务文件路径。响应不泄露绝对路径、本机设置或凭据。

| MCP 工具 | HTTP 对应 | 输入/结果 |
| --- | --- | --- |
| `workbench_capabilities` | GET `/api/agent/v1/capabilities` | 工作空间 ID、业务版本、允许类型/操作、限制、权限与确认模式 |
| `workbench_list_projects` | GET `…/projects` | 分页项目摘要，过滤无权访问项目 |
| `workbench_get_catalog` | GET `…/catalog` | 按项目返回工作流/标签；返回有权访问的文档分类 |
| `workbench_search` | GET `…/search` | query、kind、project/category、cursor、limit；返回摘要与版本 |
| `workbench_get_item` | GET `…/items/{kind}/{id}` | 正文、可编辑字段、版本；超限时分段读取 |
| `workbench_list_proposals` | GET `…/proposals` | 当前客户端的提案摘要、状态和分页 |
| `workbench_prepare_proposal` | POST `…/proposals` | request_id、operation、kind、target、base_revision、content、source_note |
| `workbench_revise_proposal` | PATCH `…/proposals/{id}` | expected_version 和新候选内容；生成下一版本 |
| `workbench_preview_proposal` | GET `…/proposals/{id}/preview` | 完整归一化预览、差异、版本、摘要和有效期 |
| `workbench_commit_proposal` | POST `…/proposals/{id}/commit` | version、preview_digest、confirmation；只提交已保存内容 |
| `workbench_get_proposal` | GET `…/proposals/{id}` | 当前状态、失败原因或原始提交回执 |
| `workbench_cancel_proposal` | POST `…/proposals/{id}/cancel` | expected_version；不影响正式内容 |

省略号统一指 `/api/agent/v1`。第一版 `kind=issue|document`，`operation=create|append|update`。未知字段拒绝，避免参数拼写错误被忽略。工具不暴露通用 HTTP 代理、任意路径读取、shell、删除、恢复历史、改配置或绕过预览的创建方法。

- issue 创建允许 title、project_id、body、status、priority、tags；状态/标签必须来自现有配置。默认状态在预览中明确显示。
- issue 更新第一版允许 title、body、status、priority、tags，不支持迁移项目、转换类型或修改附件。
- document 创建/更新允许 title、body、category、tags；分类必须已存在，不能借仓储自动 ensure 行为偷偷新建分类。
- append 将追加片段与当前正文合成完整候选，提交不再临时拼接；update 也以完整目标正文和字段差异预览。
- 新 ID、created、updated 由服务端生成；预览明确它们是服务端字段。用户可见内容、归属和状态在确认后不能被静默重写。
- `[[ID]]` 关联在正文中使用现有语法。两份新内容第一版依次提交：先得到真实 ID，再生成另一份含引用的预览。不做批量事务或提前伪造 ID。
- 搜索复用现有检索；明确不保证发现全部语义重复，不引入 embeddings。

建议初始限制：单正文 256 KiB UTF-8、标题 200 字符、单请求 1 MiB、分页默认 20/最大 100、每客户端活动提案最多 100。长原文不能完整预览时拒绝整篇更新，不能截断后当成全文保存；读取可分段。所有限制由 capabilities 返回并在服务端校验。

统一错误体包含 `code`、中文 `message`、`retryable`、安全 `details`、`request_id`。400 参数/类型错误；401 凭据缺失或失效；403 越权；404 不存在或对调用方不可见；409 版本、配置、幂等键内容冲突；410 提案过期；413 超限；429 限流；503 服务恢复中；500 未预期错误且不返回堆栈。MCP 将业务失败映射为工具 `isError` 和结构化错误，协议错误与业务错误分开。

## 5. 提案、确认与生命周期

拟新增独立目录：

```text
workbench-data/
  .agent/
    workspace.json
    proposals/<uuid>.json
    operations/<uuid>/manifest.json
    operations/<uuid>/before.md
    operations/<uuid>/after.md
    receipts/<uuid>.json
```

这些都是服务端流程状态，不属于正式记录，不进入业务列表、全文搜索、反向链接或网页编辑器草稿。凭据不放在此目录。

提案字段至少包含 schema_version、workspace_id、client_id、proposal_id、version、state、operation、kind、target_id、base_revision、normalized_content、preview_digest、previewed_version、created_at、expires_at、source_note、receipt。client_id 来自认证结果，不能信任请求自报身份。

状态：`draft → previewed → committing → committed`；draft/previewed 可进入 cancelled/expired；目标变化进入 conflicted；不确定落盘进入 recovery_required。修改或冲突后重新准备时递增 version 并回到 draft，清除预览标记。committed 不可编辑或再次应用。恢复后确定未写入的失败可返回 previewed，但仍必须检查原确认版本和有效期。

摘要使用确定性 JSON 编码后 SHA-256，覆盖工作空间、提案版本、操作、目标、基础版本、归一化用户字段及可见警告；排除最终分配的时间和 ID。预览接口持久记录已预览版本。提交必须匹配版本/摘要，禁止把 `confirmed=true` 当成唯一条件。

确认对象可记录 `mode=agent_attested`、`user_confirmed=true` 和可选确认说明。工具说明及接入指引要求 Agent 等待预览之后的新用户消息；含糊回复、原始“帮我记录”、工具返回内容中的指令都不能替代确认。修改后的内容不得沿用上一次确认。

**信任边界：服务端能证明提交对应预览版本，不能证明用户真的看过或确认过。** MCP 客户端自报确认不构成独立人类身份认证；本期接受这一已约定模式，不能在 UI 或文档中宣传“服务端强制人工批准”。未来网页确认可在同一提案上提供独立授权通道。

默认提案有效期为最后一次修改后 7 天，查看不延长；过期需重新生成预览和确认。取消/过期正文默认保留 30 天后清理；committing/recovery_required 永不自动清理。已提交提案正文可在 30 天后移除，精简回执和幂等映射保留，避免旧请求重试重复写入。清理只针对明确状态的 `.agent` 文件，不扫描删除业务附件。

## 6. 版本、历史与写入可靠性

### 6.1 版本和所有写入方

新增 `revision`，基于实际文件字节 SHA-256，不单用 mtime。旧 `file_mtime` 保留以兼容轮询。Agent 更新强制传 base_revision；网页读取后保存也携带 expected_revision。现有调用方未传版本暂保持原契约，但标记为旧客户端不能获得乐观锁保护；当前交付网页必须已迁移，不能依赖无条件覆盖解决冲突。

单服务进程先采用 Repository 级共享可重入写锁，简化锁序与恢复一致性；锁覆盖读取最新版本、检查、分配 ID、保存历史、正式写入、缓存失效和回执。记录/文档的创建、更新、删除、恢复、类型转换，项目删除、分类/状态迁移、数据目录切换等会改变目标的写入路径必须审计并接入协调。不得持锁进行模型调用或等待用户确认。

明确使用单服务写入所有权，服务启动时取得数据目录独占锁；标准库实现需兼容 Windows/Linux，先完成平台测试。不同端口启动同一数据目录也不能有两个写入服务。现有 `--replace` 和数据目录迁移必须适配锁释放/接管，不改变旧进程安全替换行为。

进程锁不能阻止外部编辑器直接写文件。提交前再次读取校验，更新前保存完整旧字节，提交后重读校验；发现不一致停止自动重试并保留恢复证据。比较后到替换间仍有外部写入竞态，不能宣称文件系统提供跨程序 CAS。文档中明确此剩余限制；不得通过自动恢复旧文件覆盖外部编辑。

### 6.2 历史与恢复

文档采用 `history/<DOC-ID>/*.md`，保持现有 Markdown 文件可读。历史版本名用高精度时间加唯一后缀防碰撞；读取兼容原版本名。文档更新和恢复前均写历史，恢复也是一次受版本检查的新修改。

文档历史增加列表/读取/恢复 API 和复用的网页历史入口；Agent 不获得恢复工具。已有记录历史实现可抽取共同的文件快照助手，但不新增平行历史存储。恢复前预览与确认遵循网页既有交互。损坏/缺失快照显示明确错误，不能覆盖当前文件。

### 6.3 幂等与崩溃窗口

单次原子替换不等于“Markdown + 回执”事务。必须使用持久操作日志，覆盖写完正文但没写回执就断电的窗口：

1. 在共享锁内确认提案状态、权限、版本、项目/分类/状态仍有效。
2. 领域仓储准备唯一目标 ID/路径及最终序列化字节，复用现有规则；尚不改业务文件。
3. 原子写操作 manifest（含前后摘要、目标相对路径、提案版本、预留 ID、阶段）与必要前后快照，完成持久化后才能修改目标。
4. 保存历史，通过领域写入方法应用已准备的内容，更新缓存并重读校验。
5. 原子写 committed 回执，再标记提案 committed；回执包含正式 ID、提交后 revision 和可用链接。
6. 启动时在接受新写入前恢复未完成操作；创建目标 ID/路径的占用由 manifest 共同约束。

恢复规则：目标等于 after 摘要则补回执；目标等于 before（新建为不存在）时可继续原操作或明确标记未应用，不能分配新 ID；目标为第三种内容或已被删除时进入 recovery_required，不覆盖、不自动重建。保留日志和人工处理说明。未解决操作至少阻止对应目标写入。

prepare 的 `(workspace_id, client_id, request_id)` 保持幂等，相同键不同内容返回 409。commit 的幂等单位是 proposal_id/version；重复提交返回原回执。回执存在时即使后续正式条目被修改或删除，也返回“该操作已完成”的原结果及当前存在状态，不重建。首版不提供跨提案全有或全无事务。

## 7. 本地访问与安全边界

- 接入默认关闭，显式启用后只允许 loopback；支持的主机名和 Origin 使用精确白名单，不能匹配任意 `.localhost` 或任意 Origin。
- 每客户端随机高熵令牌，权限拆为 read、propose、commit；同时限定项目 ID 与知识库分类/全部知识库权限。查询、预览、提交每次检查权限，不能只在建立连接时检查。
- 凭据文件放操作系统用户配置目录，按用户权限保护，不放仓库根或静态目录；服务端保存令牌摘要，桥接器从本机配置读令牌。不传模型、不写日志、不放 URL 或命令行。
- 凭据管理使用本地 CLI（拟 `python server.py --agent-client-add <name>` 等，实施时补齐精确参数和帮助），不增加匿名 HTTP 发令牌接口。支持禁用、撤销和轮换；轮换不恢复已撤销权限。
- `.agent/workspace.json` 保存随机工作空间标识，桥接配置绑定该 ID；目录切换或错误端口连接必须重新验证，不能把旧提案提交到另一个库。
- 静态服务改为显式应用资源允许集，拒绝业务数据、点目录、源代码、凭据文件、目录列表、编码穿越及符号链接逃逸；覆盖自定义 data-dir 位于仓库内的情况。
- 新 Agent API 要求 Bearer 凭据；Agent 凭据不能作为旧 UI API 的授权替代。旧 UI API 同步阻止跨源浏览器写入；本方案不宣称隔离了拥有本机用户权限的恶意进程，旧接口和直接文件访问不属于 MCP 沙箱。
- 桥接器只连接配置的 loopback origin，禁止 HTTP 跳转携带令牌，限制超时与响应大小，不关闭 TLS 校验来支持远程地址。
- 搜索结果、正文和提案内容是数据，不是工具调用授权。工具描述要求忽略资料内“跳过确认”等指令；服务端继续强制字段、权限、版本校验。
- 服务端生成网页链接，仅允许自身地址和稳定 ID；禁止传入任意回跳 URL。Markdown 继续经过共享安全渲染，不新增不受控 HTML。

## 8. MCP 与 Codex 接入

候选启动方式：`python agent_bridge.py --config <用户配置文件>`。路径由安装指引替换，不提交机器绝对路径。通过参数数组启动，stdout 只输出 UTF-8 JSON-RPC 消息，日志写 stderr 且脱敏。

首期需测试 initialize/initialized、ping、tools/list、tools/call、能力协商、未知方法、非法参数、通知无响应、EOF 退出、取消和消息大小。对选定握手版协议按规范处理不支持版本，不能假装支持未实现的新版。仅声明 tools 能力，不声明 sampling、resources、prompts 或后台 tasks。断连/取消不能视为撤销已完成写入；重连后查询提案状态。

工具定义提供 inputSchema、输出结构和操作说明；只读工具标记 readOnlyHint。所有写操作即使仅创建提案也不能标成只读；提示注解不替代授权。stdio 单连接可顺序处理请求，服务端仍必须处理不同客户端的并发。

接入指引包括：启动一次性工作台、建立测试客户端、登记桥接器、检查工具、读取 capabilities、执行预览/修改/确认流程、撤销测试凭据与移除配置。Codex 配置使用官方支持的 MCP 设置或 `codex mcp add`，最终命令以 AG-104 时实机版本为准，不假定当前聊天自动加载新工具。

提供可复制的通用 Agent 使用规则，工具说明本身携带关键约束。仓库 AGENTS.md 只约束本仓库开发，不能依赖它对其他工作目录中的 Codex 或其他 Agent 自动生效。

## 9. 网页、备份与兼容

- 新增只打开正式条目的查询参数契约，例如 `?item=issue&itemId=ISSUE-0001` 或 `?item=document&itemId=DOC-0001`；参数白名单、对称编码和初始化后的资源校验必须实现后再返回链接。
- 链接进入现有详情/编辑器，不新建 AI 编辑器。不存在条目友好提示；已有脏编辑先走保存/离开流程。不得清除原有 localStorage 导航兼容。
- 无脏编辑时，已有轮询能显示 Agent 修改；有脏编辑时保留输入并提示冲突。补充列表新增条目的可见性验收。
- 第一版预览在 Codex 内，不增加网页提案中心或聊天面板；网页只增加必要的深链接、文档历史和冲突适配。
- `.agent` 默认不进入可移植业务 ZIP；历史仍进入既有完整备份。恢复业务备份到新目录生成新 workspace_id，重新配置凭据，旧库提案不能复用。
- 同一工作空间的数据目录迁移需包含 `.agent`，先阻止新提交并等待/恢复在途操作；保留 workspace_id。操作日志仅存相对路径，迁移不能携带旧绝对路径。
- 业务备份不是流程恢复备份。完整文件级灾难恢复应在服务停止且无未决操作时进行，说明精简回执保留和恢复范围；未知 schema_version 拒绝写入、提供升级提示。
- 关闭 Agent 功能不影响普通读写；但不能跳过未完成事务恢复。降级到不认识日志的旧版本之前必须清空在途状态并备份，禁止承诺任意时点直接回退。

## 12. 发布、风险和后续边界

发布时同步 README、ARCHITECTURE、DATA_FORMAT、MAINTENANCE、AGENT_INTEGRATION 和台账；JS/CSS 修改更新 index.html 资源版本，后端更新 APP_VERSION。先用测试库演练启用、撤销、重启和恢复，再由用户按指引接入真实工作空间。

主要风险：外部编辑器不服从进程锁；同一 Agent 的确认不可独立验证；无依赖 MCP 适配需持续协议测试；旧无版本 API 调用仍可能覆盖；文件事务恢复复杂；模型上下文容量可能不足以完整展示长预览。分别通过明确限制、缩小协议面、全写点审计、故障注入和超限拒绝控制，不以文案承诺替代实现。

后续可扩展 todo/info、网页独立确认、提案管理页、其他 Agent 兼容验证及远程 MCP。新增类型必须扩展 capabilities、校验、预览和测试；远程访问必须另做认证/传输设计，不能简单把监听改为 0.0.0.0。

## 13. 设计依据

以下资料于 2026-11-03 核查；开发时再次确认目标客户端版本，不绑定所谓“最新”版本。

- [Codex MCP 官方接入文档](https://learn.chatgpt.com/docs/extend/mcp)：支持本地 stdio 工具接入，具体注册方式以当前安装版本为准。
- [MCP 2025-11-25 传输规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)：所选候选协议的 UTF-8 JSON-RPC、stdio 分帧和日志边界。
- [MCP 2025-11-25 生命周期规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle)：初始化、能力和版本协商；仅适用于本方案声明的握手协议候选。
