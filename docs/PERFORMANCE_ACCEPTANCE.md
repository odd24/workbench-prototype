# 大数据性能验收

本文件记录 RF-504 的可重复验收方法和基线结果。验收脚本只在系统临时目录生成数据，结束后自动清理，不读取或修改真实 `workbench-data/`。

## 运行方式

```powershell
python performance_acceptance.py
```

脚本使用生产仓储入口逐项写入数据，再重新实例化仓储验证磁盘事实源；随后启动临时 HTTP 服务和独立无头 Edge/Chrome，检查首页、项目、知识库、长文档和概念图，并记录主线程事件循环最大延迟。

默认规模可通过以下环境变量调整：

- `WORKBENCH_PERF_PROJECTS`：项目数，默认 12。
- `WORKBENCH_PERF_RECORDS`：记录数，默认 1200。
- `WORKBENCH_PERF_DOCUMENTS`：知识库文档数，默认 160。
- `WORKBENCH_PERF_ATTACHMENTS`：记录附件数，默认 120。
- `WORKBENCH_PERF_MARKDOWN_BYTES`：长 Markdown 目标 UTF-8 字节数，默认 1 MiB。
- `WORKBENCH_BROWSER_PATH`：无法自动发现 Edge/Chrome 时指定浏览器路径。

耗时用于识别数量级回退，不作为跨机器固定毫秒断言。硬性门禁是每个浏览器视图操作在 30 秒内完成、浏览器恢复响应，且重载后的数量、哈希、附件、ZIP CRC 和概念图节点/边全部一致。样本构造刻意逐项执行原子写与 fsync，只记录总耗时，不套用交互阈值。

## 2026-09-17 基线

测试机器：Windows 11 10.0.22631，Intel64 Family 6 Model 151 Stepping 5，8 个逻辑 CPU，Python 3.14.3，系统 Microsoft Edge。

样本：12 个项目、1200 条记录、160 篇文档、120 个附件、1 篇落盘重读后为 622,102 字符/1,048,684 字节的长 Markdown、1 张 500 节点/499 边概念图。RF-505 排除机器专属路径配置后的完整 ZIP 含 1620 个条目、763,361 字节，CRC 校验通过；搜索按既有 API 上限返回 50 条匹配。

| 1200 条记录摘要 | 434.47 ms |
| 1200 条记录签名 | 208.38 ms |
| 160 篇文档列表 | 65.57 ms |
| 搜索 | 208.43 ms |
| 完整 ZIP 导出与验证 | 3115.51 ms |

生产 API 逐项构造样本的耗时不代表正常页面操作：12 个项目 283.38 ms、1200 条记录 147,052.71 ms、160 篇文档 10,446.28 ms、120 个附件 1197.00 ms、500 节点概念图 19.97 ms。该阶段刻意保留每次写入的原子替换与 fsync，不以批量伪造文件缩短验收。

结果：所有操作均在门禁内完成，浏览器在重操作后继续响应；长 Markdown 是当前最明显的单次主线程阻塞点，但未出现超时、持续冻结或保存数据变化。后续若编辑器支持更大正文，可考虑独立评估分块渲染或虚拟化，不在 RF-504 中混入编辑器架构变化。
